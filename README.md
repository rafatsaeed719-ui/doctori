منصة طبية بتربط المرضى بأطبائهم، وبتدير العيادة والمراكز الطبية. تطبيق أندرويد ونسخة ويب (Flutter) وقاعدة بيانات Supabase.
الشركة المؤسسة: **بيثيل للتدريب والتطوير**.

## المميزات

**المريض:** يبحث عن دكتور بالتخصص والمكان، يحجز (وكمان بالعروض)، يسجّل وصوله ويشوف دوره، أدويته بمنبهات، يصوّر دوا والدكتور يحدد الجرعة، خطة علاجه ومتابعاته، روشتاته، ملفه الطبي وبياناته الصحية، شات مع الدكتور، تقييم الدكتور، إشعارات.

**الدكتور:** المرضى وملف كل مريض (الحالة حسب التخصص وخريطة الجسم والأسنان، العلاج، الروشتات، العمليات، المتابعة، الملف الطبي)، الحجوزات بالتقويم، دور الانتظار، رصيدي اليومي (دخل بأنواعه، مصروفات، صافي يومي وشهري وسنوي)، الروشتة بالطباعة أو الإرسال بشكل حسب التخصص، المتابعات بمواعيد وإشعارات، المخزن، التقارير، العمليات، الإعلانات والعروض، المساعدين بصلاحيات.

**المراكز الطبية:** مركز فيه أكتر من دكتور وأكتر من تخصص. صاحب المركز أو المدير يضيف الدكاترة ونسبة كل واحد (ونسبة لكل خدمة) ومواعيدهم والموظفين. السكرتارية تدير حجوزات ودور كل الدكاترة وتسجّل الدخل. الحسابات: دخل كل دكتور ونصيبه ونصيب المركز والمصروفات وصافي المركز.

**التحديث اللحظي:** أي حاجة تتسجل بتتحفظ فوراً وتظهر في ثانية عند كل اللي يخصهم (الدكتور ومساعدينه واستقبال المركز والمريض).

**المدير (صاحب البرنامج):** توثيق الأطباء وأكواد التفعيل، المستخدمين، بوستات على الصفحة الرئيسية، مراجعة العروض، فتح مراكز طبية.

## محتوى الكود

| المجلد | |
| --- | --- |
| `app/` | تطبيق Flutter (المريض، الدكتور، المساعد، المركز، المدير) |
| `supabase/migrations/` | قاعدة البيانات بالترتيب من `0001` لـ `0019` |
| `supabase/setup/part1.sql` و `part2.sql` | نفس القاعدة في ملفين جاهزين للتشغيل مرة واحدة (ينفع يتشغلوا تاني من غير مشاكل) |
| `supabase/tests/` | اختبارات الصلاحيات وسير العمل (300 اختبار) |
| `promo/` | ملفات الفيديو الدعائي (المشهد، الموسيقى، التعليق الصوتي) |
| `.github/workflows/` | بناء الـ APK ونسخة الويب وتحديث قاعدة البيانات تلقائياً |

## التشغيل على GitHub

- أي تعديل في `app/` بيبني APK جديد في Releases ونسخة ويب جديدة تلقائياً.
- أي تعديل في `supabase/setup/part*.sql` بيحدّث قاعدة البيانات تلقائياً. محتاج سر واحد في GitHub ← Settings ← Secrets: `SUPABASE_DB_PASSWORD` (كلمة سر قاعدة البيانات). متحطش كلمة السر دي ولا مفتاح `service_role` في أي ملف.
- بعد ما تعدّل في `supabase/migrations/` شغّل `python3 supabase/setup/build_setup.py` عشان يتحدثوا ملفات part.

## إعداد Supabase من الأول (لو مشروع جديد)

1. SQL Editor: شغّل `supabase/setup/part1.sql` وبعده `part2.sql`.
2. حط رابط المشروع والمفتاح العام (publishable) في `app/env/doctori.json` (فيه مثال في `doctori.example.json`).
3. سجّل حسابك من التطبيق، وبعدين خلّيه مدير مرة واحدة:

```sql
update public.profiles set role = 'admin' where email = 'YOUR_EMAIL@gmail.com';
```

## ملاحظات

- الإشعارات وهو مفتوح أو في الخلفية شغالة. عشان توصل والتطبيق مقفول خالص محتاجين Firebase (ملف `google-services.json`).
- الصوت في الفيديو الدعائي صوت آلي، والأفضل تسجيل صوت حقيقي قبل الاستخدام التجاري.
- العروض بتتنشر من غير موافقة مسبقة من المدير، والمدير يقدر يخفيها.
